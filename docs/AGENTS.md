
# Agent connections · Experimental

Agents Home runs a new, owned CLI session per connection and resumes only the UUID returned by that same connection during the current DeskPill lifetime. Changing its provider, executable, workspace or edit setting starts a fresh session. It does not inspect other app, IDE, cloud or CLI conversations.

Install and sign into the provider CLI separately. In connection setup, click **Find installed CLI** to discover native `codex.exe`, `claude.exe` and `gemini.exe` on PATH, the user-local bin, versioned Codex app bins, and official npm installations on PATH or in the user's npm folder. Detection runs asynchronously only when clicked; opening setup and switching provider never scan installations. Browse also accepts an official provider `.cmd` installation. DeskPill never executes or parses the batch shim: it verifies the known provider package name and bin entry in adjacent `node_modules`, then launches `node.exe` directly with that known JavaScript entry point. The accepted packages are `@openai/codex` (`bin/codex.js`), `@anthropic-ai/claude-code` (`cli.js`), and `@google/gemini-cli` (`dist/index.js`). Unknown shims, mismatched metadata, missing scripts and missing Node.js fail visibly. Installation remains manual.

Codex uses `exec --json --sandbox read-only -c approval_policy="never" --skip-git-repo-check -`, with the reviewed prompt on stdin. The connection's explicit edit switch changes only its sandbox to `workspace-write`. Resume uses the exact returned UUID after these same explicit sandbox and approval options. Claude uses `-p --verbose --output-format stream-json --permission-mode plan`, with the prompt on stdin and an exact `--resume` UUID when available. Gemini uses `--output-format stream-json --approval-mode plan -p <quoted prompt>` and an exact `--resume` UUID. Gemini plan mode may require enabling experimental planning in the CLI; unsupported versions fail visibly and DeskPill does not fall back to broader permissions. Existing provider configuration, authentication, hooks and extensions are managed by the CLI itself.

The camera button offers a reviewed area, previous external window or explicit monitor image for Codex CLI only. The UI holds one image per connection; the runtime accepts at most four per run. Initial requests place each `--image <path>` before the stdin prompt; exact-session resumes place image flags after `resume <UUID>`. Unsupported providers reject images before launching. Profile settings and image paths are snapshotted for each run. The UI owns temporary attachment files in a current-user restricted local folder. Removing/replacing an attachment, successful Send and exit delete the draft file; each run owns a separate copy until completion, failure, Stop or exit. Failed sends retain the original draft for retry. The runtime never deletes user files. Provider history may retain attachments under the provider's own policies.

App shortcut connections offer manual copy and open. They do not receive prompts or report session progress through the runtime.

Stop and exit terminate only the process job DeskPill created for that run, including descendants. The executable is created suspended and assigned to a Windows Job Object before execution; failure to assign prevents it from running. A run stops after 30 minutes. The home menu can start a new conversation while idle, clearing only that connection’s in-memory session context. One run per connection is allowed. Different connections may run independently.

DeskPill keeps drafts, session UUIDs, the current answer (at most 16,384 characters) and a conversation transcript (at most 65,536 characters) in memory; it writes no transcripts or history. The transcript retains previous prompts and answers while Copy Answer can use only the current answer. Starting a new conversation clears the transcript, last prompt and run timestamp. Activity summaries come from provider command, tool, file-change or search events; they do not invent reasoning. Each run records its actual UTC start time and reviewed prompt. A JSONL line exceeding 65,536 characters is discarded while its stream continues draining. Provider CLIs may maintain their own normal session files. CLI stderr is bounded and kept separately from the agent reply. The conversation’s info button reveals tool diagnostics and switches back to the response. Successful replies remain successful when optional connectors log authentication failures; failed runs still show Needs attention with diagnostics available. Connector authentication remains managed by the CLI; DeskPill does not disable servers or change credentials. No provider invocation, microphone access or network request occurs until explicitly requested through the respective UI.

Run `powershell -NoProfile -ExecutionPolicy Bypass -File tests/agents.ps1` for isolated fixture checks. The suite compiles into its own temporary folder, never calls a real provider and does not write into a user's workspace.

For screen questions, use the camera button to select and review an image, then Send it with your question. Window enumeration is not screen capture. An agent reporting that its own computer-use capture is blocked does not mean it received a DeskPill image. DeskPill identifies attached images as the visual context so the tool can analyze them directly; it does not relax capture permissions or enable a live desktop-control loop. Provider vision behavior remains subject to its installed model and CLI.

Capture selection activates its overlay for Escape cancellation. Moving or renaming the same source window no longer makes its remembered identity unusable; process identity is still validated. If no external window is remembered, Current monitor offers an explicit monitor capture. Capture errors stay in the conversation status instead of opening another notch view. Black-frame validation examines every pixel of the bounded image, including thin content. These changes have synthetic and UI regression coverage; physical mixed-DPI capture and provider vision responses remain unverified.
